# AI-методы и целевая архитектура – AI Pitch Deck Generator

## 1. Высокоуровневый пайплайн

Целевая система строится как многошаговый пайплайн:

1. **Сбор и нормализация входных данных**
   - Основатель заполняет структурированную анкету  
     (problem, solution, market, metrics, team и т.п.).
   - Опционально: прикладывает ссылку на сайт, one-pager, PDF-pitch и т.д.

2. **Планирование декa (LLM)**
   - LLM формирует **high-level outline**:
     - Список слайдов: заголовок + цель
     - Общая сюжетная дуга и ключевые сообщения

3. **Черновик слайдов (LLM)**
   - Для каждого слайда:
     - Генерация буллетов и заметок спикера
     - Контроль длины, стиля и тона

4. **Визуальные рекомендации (LLM + VLM)**
   - Предложения по графикам, иллюстрациям, типу диаграмм, композиции
   - При наличии бренд-материалов — учёт фирменного стиля

5. **Оценка дизайна (VLM) – будущий этап**
   - Анализ сгенерированных слайдов:
     - Слишком много текста / мелкий шрифт / слабая иерархия
   - Формирование рекомендаций по упрощению и улучшению визуала

## 2. LLM-ориентированные методы

### 2.1. Стратегии prompting’а

Рассматриваем две основные стратегии:

1. **Монолитный промпт**
   - Один большой запрос: «Сгенерируй полный deck из N слайдов по этому brief».
   - Плюсы: простая реализация.
   - Минусы: сложнее контролировать структуру и отлавливать ошибки.

2. **Пошаговый / agentic подход**
   - Шаг 1: «Сгенерируй outline (названия слайдов и их цели)».
   - Шаг 2: для каждого слайда:  
     «Сгенерируй буллеты и описание визуала, зная outline и brief».
   - Шаг 3: «Проверь консистентность между слайдами и при необходимости подправь».

Преимущества пошагового подхода:

- Легче контролировать **структуру**
- Можно **кешировать** промежуточные результаты (outline)
- Удобнее **отлаживать** и оценивать отдельные стадии

### 2.2. RAG (Retrieval-Augmented Generation)

Чтобы уменьшить галлюцинации и привязать deck к реальным данным:

- Индексируем **документы компании**:
  - Сайт, one-pager, финансовые сводки, Notion-страницы и т.п.
- Строим **векторный индекс** и запрашиваем релевантные куски:
  - Описание проблемы, сегмента клиентов, traction, метрики

LLM получает в промпте:

- Явно выделенный блок **фактов** (retrieved context)
- Чёткую инструкцию:
  - «Не придумывай факты, которых нет в контексте; при отсутствии данных — явно скажи об этом»

## 3. VLM-ориентированные методы

### 3.1. Анализ слайдов

Основные задачи для VLM:

- **Классификация типа слайда** по содержимому:
  - Problem / Solution / Market / Team / Financials / …
- Обнаружение проблем дизайна:
  - Перегрузка текстом
  - Низкий контраст текста и фона
  - Слабая визуальная иерархия, отсутствие выравнивания

Это можно использовать как:

- Автоматический «чек-лист качества» для уже существующих deck
- Обратная связь по улучшению сгенерированных LLM слайдов

### 3.2. Извлечение бренда

Вход:

- Логотип
- Фрагменты существующих презентаций
- Страницы брендбука (цвета, шрифты, визуальный язык)

VLM может:

- Определить ключевые **цвета и их комбинации**
- Описать стиль («минималистичный», «игровой», «корпоративный» и т.д.)
- Выделить типы иллюстраций/фото: сток, flat-иллюстрации, реальные фото и т.п.

LLM затем использует эти данные при генерации `visuals_description`:

- Например: «Иллюстрация в фирменной палитре (#112233, #44AAFF)  
  с плоскими фигурами и крупным жирным заголовком».

## 4. Концептуальная архитектура системы

### 4.1. Компоненты

- **Frontend**
  - Веб-интерфейс для основателя:
    - Анкета
    - Предпросмотр deck
    - Возможность правок / регенерации отдельных слайдов

- **Backend API**
  - Оркестратор пайплайна:
    - LLM-планировщик deck
    - LLM-генератор слайдов
    - (опционально) RAG-модуль
    - (опционально) VLM-оценка дизайна

- **Хранилище**
  - База данных для:
    - Брифов и версий deck пользователей
    - Результатов экспериментов и метрик (в ЛР 2 — локальный SQLite с таблицами `examples`, `experiments`, `predictions`)
