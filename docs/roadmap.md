# ROADMAP проекта AutoPitch Deck Generator

## Эпики и структура спринтов

### Эпик 1. Базовая инфраструктура и ядро приложения

Цель: запустить фундамент: аутентификация, БД, базовый фронтенд, загрузка файлов.

### Спринт 1 (1 неделя): Основы системы

**Задачи:**
- Архитектурная схема (C4) и финализация требований
- Настройка репозиториев
- Настройка SQL
- Имплементация аутентификации 
- Структура БД: пользователи, проекты, файлы
- Базовый UI: вход/регистрация, дашборд
  
**Зависимости: нет**

**MVP: частично**

### Эпик 2. Модуль загрузки и парсинга презентаций (AI Parser)

Цель: загрузка .pptx/.pdf и извлечение текста, изображений, структуры.

### Спринт 2 (1 неделя): Загрузка и хранение файлов

**Задачи:**
- Модуль загрузки презентаций
- Валидация и ограничение размера (до 100 МБ)
- Интеграция с облачным хранилищем (Google Drive API?)
- Создание очередей Celery для обработки файлов
- UI: экран загрузки

**Зависимости: Эпик 1**

**MVP: да**

### Спринт 3 (1 неделя): AI Parser

**Задачи:**
- Извлечение текста из PDF (PDFMiner / PyMuPDF)
- Парсинг PPTX (python-pptx)
- Выделение структуры слайдов (хедеры/блоки/списки)
- API выдаёт JSON со структурой
- Логирование и обработка ошибок

**MVP: да**

### Эпик 3. LLM-оптимизация контента / генерация текста

Цель: улучшение и сокращение входящей презентации + генерация структуры для новой.

### Спринт 4 (1 неделя): Обработка текста существующей презентации

**Задачи:**
- Связка с LLM-API (OpenAI / Anthropic)
- Алгоритм сокращения текста
- Логика “ключевых смыслов”
- API: /optimize_presentation
- UI: предпросмотр текста

**MVP: критически важно**

### Спринт 5 (1 неделя): Генерация презентации с нуля

**Задачи:**
- LLM-промпты для структуры 10–12 слайдов
- Генерация контента по разделам (Проблема, Solution, Team и т.д.)
- Объединение в JSON-структуру
- API: /generate_from_scratch
- UI: форма ввода описания стартапа

**MVP: вторично (опционально, если сроки сжаты)**

### Эпик 4. AI Design Engine — визуальный стиль, рендеринг, экспорт

Цель: применение шаблонов дизайна, рендеринг предпросмотра, экспорт PPTX/PDF.

### Спринт 7 (1 неделя): Рендеринг предпросмотра + редактор

**MVP: да**

## MVP-функции (только самое важное)
**MVP обязательно включает:**
- Аутентификация + хранение пользователей
- Загрузка PPTX/PDF
- Парсинг и извлечение структуры
- Оптимизация текста через LLM
- Один базовый шаблон дизайна
- Простая предпросмотрная визуализация
- Экспорт PPTX/PDF

**MVP НЕ включает:**
- Генерация презентации “с нуля”
- Расширенные шаблоны дизайна
- Интерфейс полного редактирования слайдов
- Интеграции с Figma

## Зависимости задач:
- Все модули зависят от базовой инфраструктуры — сначала должны быть готовы backend, база данных и аутентификация, иначе невозможно хранить проекты и вызывать API.
- Загрузка файлов должна быть реализована до парсинга, потому что парсер работает только с уже сохранёнными презентациями.
- Парсинг должен быть выполнен до оптимизации текста, так как LLM может улучшать и сокращать контент только после того, как система его извлечёт из файла.
- Оптимизация текста должна быть выполнена до применения дизайна, потому что стиль накладывается на финализированные тексты и структуру слайдов.
- Дизайн должен быть готов до предпросмотра и редактирования, потому что пользователю нужно видеть уже оформленные слайды.
- Предпросмотр должен быть сделан до экспорта, так как экспорт формирует PDF/PPTX на основе окончательной версии слайдов.
- Генерация презентации с нуля зависит только от инфраструктуры и LLM, но всё равно должна пройти через дизайн, предпросмотр и экспорт как и обычная презентация.

## Риски

### Риск: Долгое время рендеринга шаблонов
- Митигация: Предварительная генерация CSS-шаблонов, оптимизация SVG

### Риск: Нестабильный парсинг PDF
- Митигация: Fallback: OCR, упрощённый режим без сохранения изображений

### Риск: Непредсказуемость LLM в генерации структуры
- Митигация: Жёсткие промпт-шаблоны, температурные ограничения

### Риск: Проблемы экспорта PPTX (сложная верстка)
- Митигация: Ограничение стилей в MVP, модульные компоненты слайдов
