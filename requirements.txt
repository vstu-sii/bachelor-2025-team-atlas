# Требования к моделям


## 1. Задача

Цель: по короткому описанию стартапа автоматически генерировать текст питч-дека  
(структура слайдов + заголовки + буллеты) на английском языке.

Базовый функционал baseline-версии:
- Создание структуры дека (≈10–12 слайдов).
- Генерация заголовков и тезисов для каждого слайда.
- Перегенерация отдельных слайдов по запросу.
- Управление стилем (формальный / storytelling / технический; целевая аудитория — VC / акселератор и т.п.).

В baseline **не входит**: визуальный дизайн, верстка слайдов, генерация картинок.

---

## 2. Типы моделей

- **LLM (основная модель)**
  - Генерация структуры и текста слайдов.
  - Поддержка инструкций и форматированного вывода (JSON / markdown).

- **Модель эмбеддингов**
  - Векторизация описаний стартапов и примеров хороших питч-деков.
  - Поиск похожих кейсов (RAG) и подмешивание примеров в промпт.

- **VLM / генерация картинок (опционально, не в baseline)**
  - Идеи для визуалов на слайдах. Интеграция — в следующих спринтах.

---

## 3. Требования к LLM

**Функциональные:**
- Генерировать упорядоченный список слайдов с полями:
  - `id`, `title`, `bullets` (и при необходимости `goal`/`notes`).
- Обязательные разделы: Problem, Solution, Market, Business Model, Traction, Team, Roadmap, Ask.
- Управление тоном и аудиторией через параметры запроса.

**Качество:**
- **Accuracy (доменные правила):**
  - Наличие всех обязательных разделов.
  - Тезисы опираются на входной бриф (без явных противоречий).
- **Текстовые метрики:** BLEU, ROUGE — на тестовом наборе эталонных деков.
- **Hallucination:** отслеживаем долю выдуманных фактов (особенно цифры, инвесторы, партнёры).

**Производительность:**
- Генерация полного дека (10–12 слайдов): P95 ≤ 12 сек.
- Перегенерация одного слайда: P95 ≤ 3 сек.
- Контекст: ≥ 8k токенов (желательно 16k+).

**Стоимость и ограничения:**
- Ориентировочная стоимость одной генерации дека: до $0.02–0.05.
- Провайдер и конкретная модель задаются через конфиг/переменные окружения.
- Данные пользователей не используются для дообучения моделей провайдера.

---

## 4. Требования к эмбеддингам

Назначение:
- Поиск похожих питч-деков по индустрии и стадии.
- RAG: подмешивание примеров и best practices в промпт LLM.

Требования:
- Вектор + метаданные: `industry`, `stage`, `quality`, `source_id`.
- Косинусная близость / dot product.
- Батч-кодирование (10–20 текстов) < 300 мс на CPU.

---

## 5. Метрики и логирование

**Качество:**
- Accuracy по структуре (обязательные разделы на месте).
- BLEU/ROUGE между предсказанием и эталоном.
- Ручные оценки (эксперт): структура, ясность, “готовность для инвестора”, правдоподобие (1–5).

**Производительность:**
- Latency P50/P95 для генерации дека и слайда.
- Частота ошибок API / таймаутов.

**Hallucinations:**
- Количество выдуманных фактов на тестовом наборе.
- Отдельно считаем опасные факты (деньги, имена инвесторов, партнёры).

Все вызовы LLM и эмбеддингов логируются и трассируются через **Langfuse**.

---

## 6. Ограничения по инфраструктуре

- Язык: Python 3.11+.
- API: FastAPI (или аналогичный фреймворк).
- Целевая среда: Docker-контейнер, облачный инстанс 2–4 vCPU, 8–16 ГБ RAM.
- Модели и ключи конфигурируются без изменения кода (через env/config).
